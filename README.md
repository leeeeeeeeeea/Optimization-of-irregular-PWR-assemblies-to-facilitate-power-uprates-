# Optimization-of-irregular-PWR-assemblies-to-facilitate-power-uprates-
This is a master's project for a masters in nuclear engineering from the University of Cambridge. I have worked on of the position of pins in an irregular assembly using Serpent and WIMS (determinist code) for neutronics and Cobra for thermodraulics

The Cobra codes are taken mostly directly from Ben Lindley. In his repository you will also find codes for neutronics simulation using Open MC, which I have not used but could be of interest, as well as the original subchannels and pins list.Serpent and WIMS codes shown here were written by me, as were all the optimizations. 
 
Workflow for the power peaking optimization : 
- The optimization code proposes a set of pin positions 
- The objective function is called to evaluate the power peaking and MDNBR 
- First, we check that the geometry is allowed. If a pin is too close to another pin or overlaps with a guide tube, the objective function immediately returns a figure of merit of F=100. The rest of the loop does not happen. If not, we continue : 
- The code BL324 1/8 maker.py generates the Serpent or WIMS input code (BL324 1/8 for Serpent, input for WIMS), 
- Serpent or WIMS runs with a subprocess.run command from the objective function, 
- The calc P function gets the Serpent/WIMS results from the BL324 1/8 det0.m/output file to get the power of each pin, 
- The  heat map function uses this pin power list to calculate the power peaking and to draw the map of the assembly with the relative power of each pin. The figure of merit F is the power peaking, 
- Using the pin powers a COBRA input is generated by the function cobra  input, 
COBRA is run with a subprocess.run command, with worse conditions than the average assembly to get the real MDNBR, 
- The function cobra output reads from the output file OUTFILE to get the MDNBR and the pressure drop of the assembly, 
- If the MDNBR is too low, the figure of merit is set at F=100, 
- End of the objective function, the figure of merit is returned to the optimizer. The optimizer can generate a new set of pin positions.  


Some technical points :  
 - The numbering of pins here is mine, it is different from Ben Lindley's. It is not to be changed. Although many subchannels are generated automatically, the edges are added manually and still depend on the pin numbers.  
- I have given you some examples of input and output files for all the different codes (Serpent, WIMS, Cobra) so that you can check if you need to. However I am not exactly sure what these files are for (they might be for the original BL324, for an optimal assembly, a test with different Serpent parameters...). The one thing to trust are the Python codes, they hold all of the information anyways. 
- A "ps2pdf postscript.ps" call in my personal computer's terminal is how I managed to transform the postscript geometry output from WIMS into a PDF.  
- The command "nohup python3 master.py &" is how I ran my codes on the server. This keeps the script running on the server even if you close your ssh and allows you to see tqdm progress if you are running a test (or any other printed output) in a nohup.out file. The "&" at the end of the command means that it prints out the number of the job, so you can kill it if you need to.
